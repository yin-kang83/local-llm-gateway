# 本地部署实测（本机基线）

> 目的：记录"这套东西在这台机器上到底能不能跑、跑多快"，避免只凭感觉评估。
> 数据由 `llm-gateway bench` 实测生成；机器变了就重跑并更新本文件。

## 1. 本机硬件（2026-11-27）

| 项 | 值 |
|---|---|
| CPU | Intel Core i5-8250U（4 核 8 线程） |
| 内存 | 7.9 GB DDR4-2133（板载，不可升级） |
| GPU | NVIDIA MX150 2 GB（另有 Intel UHD 620 核显） |
| 部署位置 | 便携版目录自选（下文记作 `<OLLAMA_DIR>`）；模型默认落 `%USERPROFILE%\.ollama` |

## 2. 模型选型

| 模型 | 体积（Q4） | 内存占用 | 用途 | 结论 |
|---|---|---|---|---|
| `qwen2.5:1.5b` | ~1.0 GB | ~2.5 GB | 财务实体抽取（JSON） | 主力候选 |
| `qwen2.5:0.5b` | ~0.4 GB | ~1.2 GB | 极速兜底/分类 | 备选 |
| 7B 级 | ~4.5 GB+ | > 8 GB | — | 本机不可行（内存不足） |

**显存提醒**：MX150 只有 2 GB，1.5B 模型部分卸载到 GPU 容易反复换页，反而慢于纯 CPU。
默认让 Ollama 用 CPU 推理；是否开 GPU 以本文件实测数据为准。

## 4. 安装记录（可复现）

```powershell
# 1) 便携版解压（不写注册表、不装服务）到 <OLLAMA_DIR>
# 2) 启动服务（后台常驻）
<OLLAMA_DIR>\ollama.exe serve
# 3) 拉模型（走本地/镜像网络，失败即停，不换源硬凑）
<OLLAMA_DIR>\ollama.exe pull qwen2.5:1.5b
# 4) 自检
curl http://127.0.0.1:11434/api/tags
```

### 已知坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 下载 `github.com:443` 超时 | 直连时通时断 | 用镜像前缀（如 `gh-proxy.com`）下载同一 URL，并用大小/校验确认 |
| 模型列表为空 | 服务没起或 `OLLAMA_MODELS` 指错 | `ollama serve` 前台跑一次看日志 |
| 首次调用很慢 | 模型加载进内存 | bench 前先 warm-up（本工具默认 warmup=1，不计入统计） |
| 内存吃紧 | 7.9 GB 是硬上限 | 只用 1.5B 及以下；一次只跑一个模型；不要并行多请求 |
